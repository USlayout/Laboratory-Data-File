## 要約

sysbench CPUは4環境でほぼ同等。fioランダムI/OはKVM/DOKでIOPS低下とレイテンシ増加が見られ、iperf3 UDPは仮想環境側の損失率が高い。Memory READとfio Sequential READは平均値および標準偏差に環境差がある。原因は生データ・環境情報不足のため断定できない。iperf3グラフのn=10と設定IPERF_RUNS=1の不一致を最優先で確認する。ECoreのデータがなくP/E比較はできない。

## 改善案・再測定

1. vCPU数、ホストCPU pinning対応、メモリ上限、仮想ディスク形式/キャッシュ、ファイルシステム、物理デバイスを記録し、affinity 0〜3が同条件か確認する。
2. iperf3の実行回数とグラフnを一致させ、各runのJSON/stderrとサーバ側結果を保存する。
3. UDPは複数送信レートで測定し、受信帯域・loss・jitterをJSONから記録する。
4. fioは各runのJSONと全試行値を保全し、中央値・平均・標準偏差・外れ値基準を報告する。対象デバイスとキャッシュ設定を揃える。
5. sysbench memoryは環境間で実行順を入れ替え、CPU周波数・温度・バックグラウンド負荷、working set条件を記録する。
6. P/E比較は同じスクリプト、スレッド数、反復数で行い、物理コア種別とCPU IDを記録する。ECoreデータ取得後に比較。
7. 測定時のbenchmark.confのコピーかチェックサムを実験データに含める。

## 調査優先度

1. iperf3実行回数とn=10表記の不一致、集計元。
2. fioランダムI/Oを生JSON、対象デバイス、仮想ディスク設定で確認。
3. UDP損失をJSON・サーバログと複数レートで再測定。
4. Memory READのaffinity、周波数、負荷、working setを確認。
5. ECoreの同条件データを取得してP/E比較。

## 結論

グラフ上、CPU演算とTCP帯域は概ね近い一方、fioランダムI/OとUDP損失に環境差がある。Memory READとSequential READにはばらつきがある。生データ不足のため原因は確定できない。iperf3の実行回数を照合し、生JSONと測定時設定を確認してから再解析する。
